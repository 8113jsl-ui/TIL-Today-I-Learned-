# SQLite의 역할과 데이터베이스 선택 기준

학습일: 2026-08-27

수업에서 Flask와 SQLite로 할 일 앱을 만드는 구성을 접했다. 필기에는 SQLite를 모바일에서 파일로 저장하는 방식으로 적었는데, 모바일 전용 기술은 아니다.

## SQLite는 무엇인가

SQLite는 애플리케이션에 포함해서 사용할 수 있는 SQL 데이터베이스 엔진이다. 별도의 데이터베이스 서버 프로세스를 운영하지 않고 데이터를 관리할 수 있다.

파일 기반 데이터베이스를 사용하면 프로그램을 종료한 뒤에도 데이터를 보관할 수 있다. 메모리에만 만드는 데이터베이스도 있으므로, 어떤 연결 방식을 사용했는지 구분해야 한다.

## 할 일 앱에서의 위치

복습용 구조는 다음과 같이 생각할 수 있다.

사용자 입력 → Flask의 검증과 처리 → SQLite 저장 → 처리 결과 응답

이 구성에서는 서버 애플리케이션이 데이터베이스를 다룬다. 브라우저가 서버의 데이터베이스 파일을 직접 열어서 고치는 구조가 아니다.

## 선택할 때 확인할 점

| 확인할 점 | 생각해 볼 질문 |
| --- | --- |
| 운영 구조 | 별도 DB 서버를 관리해야 하는가? |
| 동시 쓰기 | 여러 요청이 동시에 많은 데이터를 수정하는가? |
| 배포 구조 | 여러 서버가 같은 데이터를 공유해야 하는가? |
| 데이터 보관 | 배포 후에도 파일이 유지되고 백업되는가? |

SQLite는 로컬 앱이나 간단한 웹 서비스에도 사용할 수 있다. 반면 여러 서버가 네트워크를 통해 공동 데이터베이스를 사용하거나 동시 쓰기가 많은 경우에는 클라이언트·서버 방식의 DB를 검토할 수 있다.

'작은 프로젝트는 무조건 SQLite, 큰 프로젝트는 무조건 다른 DB'처럼 이름만으로 결정하기보다 접근 방식과 쓰기 부하를 확인해야 한다.

## 복습한 내용

데이터베이스를 사용한다는 것과 별도 데이터베이스 서버를 운영한다는 것은 같은 말이 아니다. 실습에서는 간단한 구조로 시작하되, 데이터 파일의 위치와 보관 방법까지 이해하고 사용해야 한다.
