# [SQL] GROUP BY와 HAVING으로 지역별 주문 합계 구하기

원문: [Velog](https://velog.io/@8113jsl-ai/sql-group-by-having-practice)

주문 내역이 여러 줄 쌓여 있을 때, 지역별로 얼마씩 주문했는지 한눈에 보고 싶을 수 있어요. 이번에는 작은 주문 표를 놓고 GROUP BY와 HAVING을 함께 써보려고 합니다.

문제와 데이터는 학습용으로 새로 구성했어요. 특정 코딩테스트 사이트의 문제를 옮긴 글은 아니며, 실행 결과는 SQLite 기준입니다.

## 주문 다섯 건을 지역별로 묶어볼게요

서울과 부산에는 주문이 두 건씩, 대전에는 한 건이 있다고 해볼게요. 금액은 NULL이 없는 0 이상의 정수로 다룹니다. 아래 SQL을 실행하면 같은 데이터를 준비할 수 있어요.

```sql
CREATE TABLE orders (region TEXT, amount INTEGER);
INSERT INTO orders VALUES
  ('서울', 12000), ('부산', 8000),
  ('서울', 9000), ('부산', 7000), ('대전', 5000);
```

여기서 지역별 주문 합계가 15,000원 이상인 곳만 찾아보겠습니다. 합계가 큰 순서로 보여주고, 합계가 같으면 지역명 오름차순으로 정렬할게요.

서울의 주문은 두 건이지만 결과에서는 서울이 한 줄로 나와야 해요. 그래서 묶을 기준은 region, 더할 값은 amount가 됩니다.

## 합계를 구한 다음 조건을 걸어요

```sql
SELECT region, SUM(amount) AS total_amount
FROM orders
GROUP BY region
HAVING SUM(amount) >= 15000
ORDER BY total_amount DESC, region ASC;
```

SQLite에서 확인한 결과는 다음과 같아요.

| region | total_amount |
| --- | ---: |
| 서울 | 21000 |
| 부산 | 15000 |

서울은 12,000원과 9,000원을 더해 21,000원이에요. 부산은 합계가 정확히 15,000원이므로 조건에 포함되고, 대전은 5,000원이어서 빠집니다.

## WHERE로 걸러도 같을까요?

조건을 쓰는 자리라고 하면 WHERE가 먼저 떠오를 수 있어요. 하지만 여기서는 무엇에 조건을 거는지 구분해야 합니다.

WHERE는 그룹을 만들기 전의 개별 행을 거르고, HAVING은 그룹을 만든 뒤 그 그룹이 조건에 맞는지 확인해요. 따라서 WHERE amount >= 15000이라고 쓰면 주문 한 건이 15,000원 이상인 행만 남습니다. 이번 데이터에는 그런 주문이 없어서 결과가 비게 돼요.

우리가 필요한 것은 지역별 합계가 15,000원 이상인지 확인하는 일이죠. 그래서 HAVING SUM(amount) >= 15000을 사용합니다.

이 흐름은 행 선택 → 그룹 생성 → 그룹 조건 확인 → 정렬 순서로 이해하면 편해요. 다만 이해를 위한 논리적 흐름이고, 데이터베이스가 내부에서 실제로 일하는 순서와 항상 같다는 뜻은 아닙니다.

## 결과의 한 줄이 무엇인지 먼저 생각해요

이번 실습에서는 결과 한 줄이 주문이 아니라 지역을 뜻했어요. 이 기준을 먼저 정하면 GROUP BY에 어떤 컬럼을 넣을지도 자연스럽게 연결됩니다.

또 GROUP BY만으로 출력 순서까지 정해지는 것은 아니에요. 원하는 순서가 있다면 ORDER BY로 명시해 주세요. 이 글의 결과는 자체 데이터로 실행해 확인한 것이며, 사이트 채점 기록은 아닙니다.
