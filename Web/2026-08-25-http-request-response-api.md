# 브라우저·서버와 HTTP 요청·응답

학습일: 2026-08-25 · 정리일: 2026-09-24

수업 필기.txt의 해당 날짜 구간을 바탕으로 정리했다. 용어 설명과 예제는 복습을 위해 보완했으며 수업 전체 기록은 아니다.

## 요청에서 화면까지

브라우저는 필요한 자원에 대한 요청을 보내고, 서버는 요청을 처리한 결과를 응답한다. 브라우저는 받은 HTML 등을 해석하고 추가 자원을 요청해 화면을 구성한다. HTTP 응답은 HTML뿐 아니라 JSON, 이미지 등 다양한 내용을 전달할 수 있다. [MDN HTTP 개요](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Overview)

```text
클라이언트 → HTTP 요청 → 서버
클라이언트 ← HTTP 응답 ← 서버
```

| 요소 | 역할 |
| --- | --- |
| 메서드 | 요청 의도 표현: GET, POST 등 |
| URL | 요청할 자원의 위치 |
| 요청 헤더 | 요청 처리에 필요한 부가 정보 |
| 응답 상태 코드 | 처리 결과 표현 |
| 응답 본문 | 데이터 또는 문서 등 실제 내용 |

## API와 화면은 다르다

API는 프로그램끼리 상호작용하는 인터페이스다. 웹 API는 HTTP를 이용할 수 있지만, 모든 API가 웹 API인 것은 아니다. 화면은 API 응답을 받아 사용자에게 적합한 형태로 보여줄 수 있다.

예를 들어 재고 조회 API가 수량을 JSON으로 반환하면 화면은 이를 숫자와 품절 표시로 바꿔 보여준다. API의 데이터와 화면의 표현을 분리해서 이해한다.

## 요청·응답에서 오해하기 쉬운 점

HTTP가 요청·응답 구조라는 사실이 브라우저 전체가 응답 때까지 멈춘다는 뜻은 아니다. 비동기 요청으로 다른 작업을 계속할 수 있으며, 네트워크 오류나 시간 초과로 응답을 받지 못할 수도 있다.

또한 POST라고 전송 내용이 암호화되는 것은 아니다. 전송 구간 보호에는 HTTPS가 필요하다. 민감한 값을 URL에 넣으면 기록과 공유 과정에 남을 수 있으므로 요청 위치와 전송 보호를 별도로 검토한다. 이 부분은 8월 27일 관련 필기를 함께 보완한 내용이다.
