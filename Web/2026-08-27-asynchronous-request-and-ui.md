# 비동기 요청과 화면의 대기 상태

학습일: 2026-08-27

수업에서 HTTP 요청·응답과 비동기를 배웠다. 필기에는 응답이 올 때까지 아무 동작도 못한다고 적었는데, 요청·응답 구조 자체가 화면 전체를 멈추게 하는 것은 아니다.

## 비동기가 필요한 이유

네트워크 요청은 응답까지 시간이 걸릴 수 있다. 비동기 방식은 이런 작업이 끝나기를 기다리는 동안 다른 작업을 진행하고, 결과가 준비되면 이어서 처리할 수 있게 한다.

할 일 목록을 불러오는 동안 사용자가 다른 입력란을 작성할 수 있는 화면을 생각하면 이해하기 쉽다. 비동기는 React만의 기능이 아니며, 일반 JavaScript에서도 사용할 수 있다.

## 화면에는 여러 상태가 필요하다

복습용으로 목록 조회 화면을 다음처럼 나누어 보았다.

| 상태 | 화면에서 할 일 |
| --- | --- |
| 요청 전 | 조회 버튼이나 초기 안내 표시 |
| 대기 중 | 불러오는 중임을 표시 |
| 성공 | 응답받은 목록 표시 |
| 실패 | 오류와 다시 시도할 방법 안내 |

요청을 보냈다는 사실만으로 성공 화면을 보여 주면 안 된다. 응답 결과를 확인한 뒤 상태를 바꾸어야 한다.

## 응답 순서도 생각하기

사용자가 검색어를 연속으로 바꾸면 먼저 보낸 요청의 응답이 나중에 도착할 수도 있다. 화면에 마지막 검색어의 결과를 표시하려면, 도착한 응답이 현재 검색에 해당하는지 확인하는 처리가 필요하다.

또한 비동기라고 계산량이 큰 코드가 자동으로 빨라지는 것은 아니다. JavaScript에서 오래 걸리는 동기 계산을 실행하면 화면 반응이 느려질 수 있다.

## 복습한 내용

HTTP는 요청과 응답의 규칙이고, 비동기는 작업 완료를 기다리고 이어서 처리하는 방식에 관한 개념이다. 둘을 구분해야 '서버가 느린 것인지, 화면의 처리 방식이 문제인지' 살펴볼 수 있다.
