# HTTPS가 보호하는 범위

학습일: 2026-08-28

필기에는 HTTPS를 인증서가 발급된 안정적인 서비스라고 적었다. 통신을 보호하는 것과 서비스 전체의 품질을 보장하는 것은 구분해야 한다.

## HTTP와 HTTPS

HTTPS는 TLS로 보호되는 HTTP 통신이다. 통신 중 데이터의 기밀성과 무결성을 보호하고 인증서를 통해 접속 대상의 신원을 확인하는 데 사용된다.

주소가 HTTPS라고 해서 내용이 사실이거나 운영자가 믿을 만하다는 뜻은 아니다. 서버의 프로그램 오류나 잘못된 접근 권한 설정까지 자동으로 해결되는 것도 아니다.

## POST와도 구분하기

GET과 POST는 요청 메서드의 차이다. POST의 본문에 데이터를 넣는 것만으로 전송 내용이 암호화되는 것은 아니다. 암호화된 통신을 위해서는 HTTPS 같은 전송 보호가 필요하다.

HTTPS를 사용하더라도 URL에 민감한 값을 넣으면 브라우저 기록이나 서버 로그 등에 남을 수 있다. 통신 암호화와 기록 위치는 따로 생각해야 한다.

## 복습용 확인 질문

- 브라우저와 서버 사이의 통신은 보호되는가?
- 인증서 경고가 발생하는가?
- 서버는 요청한 사용자의 권한을 확인하는가?
- 민감한 값이 URL이나 로그에 남는가?

## 복습한 내용

HTTPS는 중요한 통신 보호 장치다. 인증서가 있다는 이유만으로 서비스의 정확성, 가용성, 사용자 권한 관리까지 보장된다고 표현하면 안 된다.
