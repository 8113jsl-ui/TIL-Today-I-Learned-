# AI 답변을 다른 모델로 확인할 때의 한계

학습일: 2026-08-27

수업에서 한 모델이 만든 결과를 다른 모델에게 검토시키는 방법을 배웠다. 다른 관점을 얻는 데 도움이 되지만, 두 모델이 동의한다고 사실이 증명되는 것은 아니다.

## 검토 의견과 검증 근거

다른 모델에게 빠진 조건, 논리의 비약, 반례를 찾아 달라고 요청할 수 있다. 이후에는 원문 자료나 실행 결과와 대조해야 한다.

| 결과물 | 복습용 검증 기준 |
| --- | --- |
| 기술 설명 | 공식 문서와 실제 동작 |
| 계산 결과 | 입력값과 독립적인 재계산 |
| 코드 | 요구사항과 실행 결과 |
| 요약문 | 제공한 원문의 해당 부분 |

## 평가 기준부터 정하기

답변이 좋은지만 묻기보다 필수 항목, 형식, 사실 정확성 등 확인할 항목을 정한다. 평범한 입력뿐 아니라 빈 입력이나 애매한 요청처럼 실패하기 쉬운 경우도 평가에 넣는다.

문서 요약이라면 핵심 항목을 포함했는지와 원문에 없는 사실을 추가했는지를 따로 살펴볼 수 있다. 모델의 자신감 있는 말투는 검증 근거가 아니다.

## 복습한 내용

교차검토는 오류를 찾는 보조 수단으로 쓰고 최종 판단에는 확인 가능한 근거를 남겨야 한다. 프롬프트를 수정한 뒤 같은 평가 사례로 다시 확인하면 개선 여부를 비교하기 쉽다.
