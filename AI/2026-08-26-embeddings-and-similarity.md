## 임베딩은 숫자로 표현한 데이터다

필기의 ‘임베딩 = 벡터’는 데이터를 수치 표현으로 변환한다는 관점에서 이해한다. 텍스트 임베딩은 모델을 통해 텍스트를 벡터로 표현하고, 같은 공간에서 가까운 표현을 비교할 수 있게 한다. 단어를 단순한 동의어 목록으로 치환하는 것과는 다르다. [Google 임베딩 설명](https://developers.google.com/machine-learning/crash-course/embeddings/embedding-space)

## 검색의 흐름

1. 검색 대상 문서를 적절한 단위로 나눈다.
2. 각 문서를 같은 임베딩 모델로 벡터화한다.
3. 질문도 호환되는 같은 공간의 벡터로 바꾼다.
4. 유사도를 계산해 후보를 찾는다.
5. 원문과 조건을 확인해 실제로 필요한 결과인지 검토한다.

‘반려견 보험’과 ‘강아지 보험’처럼 표현이 달라도 관련 문서를 찾는 데 사용할 수 있다. 다만 실제 검색 품질은 모델, 문서 분할, 데이터에 따라 달라진다.

## 보충 예제: 코사인 유사도

다음 벡터는 계산 설명용으로 만든 숫자이며 실제 문장 임베딩이 아니다.

```python
from math import sqrt

def cosine(a, b):
    if len(a) != len(b):
        raise ValueError("벡터 차원이 다르다")
    norm_a = sqrt(sum(x * x for x in a))
    norm_b = sqrt(sum(x * x for x in b))
    if norm_a == 0 or norm_b == 0:
        raise ValueError("영벡터의 방향은 정의하지 않는다")
    return sum(x * y for x, y in zip(a, b)) / (norm_a * norm_b)

print(round(cosine([1, 0], [1, 1]), 3))
print(round(cosine([1, 0], [0, 1]), 3))
```

예상 출력은 0.707과 0.0이다. 숫자가 크다고 사실이 정확하거나 사용자에게 반드시 적합하다는 뜻은 아니다. 유사도는 후보를 고르는 기준이고, 정답 여부는 별도 검증 대상이다.
