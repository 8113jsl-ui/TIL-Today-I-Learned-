# AI 에이전트·도구 호출·MCP의 역할

학습일: 2026-08-26 · 정리일: 2026-09-24

수업 필기.txt의 해당 날짜 구간을 바탕으로 정리했다. 용어 설명과 예제는 복습을 위해 보완했으며 수업 전체 기록은 아니다.

## 답변과 작업 실행을 구분하기

필기는 AI 에이전트를 후속 업무까지 처리하는 서비스로 설명했다. 실무 관점에서는 목표를 위해 모델이 도구 사용과 다음 행동을 선택하고, 결과를 받아 작업을 이어가는 구조로 이해할 수 있다. 자율성의 정도와 실행 범위는 시스템 설계에 따라 달라진다.

날씨를 설명하는 답변과 날씨 API를 조회해 실제 데이터를 가져오는 행동은 다르다. 도구 실행에는 입력값, 권한, 오류 처리, 결과 확인이 필요하다.

## 도구 목록을 전달하면 자동 실행되는가

`tools = TOOLS` 같은 한 줄만으로 AI나 실행 루프가 완성되는 것은 아니다. 일반적으로 애플리케이션이 도구 정의를 제공하고, 모델이 도구 호출을 요청하면 실행 계층이 이를 검증해 실행한 뒤 결과를 전달한다.

```text
사용자 목표
 → 모델의 도구 호출 요청
 → 입력·권한 검증
 → 도구 실행
 → 결과 또는 오류 전달
 → 다음 행동 또는 최종 응답
```

위 흐름은 이해를 위한 개념도이며 실행 코드는 아니다.

## MCP는 연결을 위한 프로토콜이다

MCP는 AI 애플리케이션과 외부 기능·데이터를 연결하는 표준화된 통신 구조를 제공한다. 호스트 안의 클라이언트가 서버와 연결하며, 서버는 도구·리소스·프롬프트 등의 기능을 제공할 수 있다. MCP 자체가 모델이거나 모델의 판단을 검증하는 장치는 아니다. [MCP 아키텍처](https://modelcontextprotocol.io/docs/learn/architecture)

모델 API를 호출하는 모든 애플리케이션에 MCP가 필수인 것도 아니다. 일반 API나 직접 구현한 함수 호출로 연결할 수도 있다.

## 설계할 때 확인할 것

날씨 조회처럼 읽기만 하는 작업과 예약·발송처럼 외부 상태를 바꾸는 작업을 구분한다. 실패 시 재시도 횟수와 중단 조건도 정한다. 도구가 오류를 반환했는데 성공했다고 답하지 않도록, 실행 결과에 근거해 사용자에게 보고해야 한다.
