# CI/CD와 자동화된 검증 흐름

학습일: 2026-08-28

필기에 CI/CD라는 용어만 남아 있어 공식 문서로 의미를 보완했다. 코드를 저장소에 올리는 것, 검사하는 것, 사용자에게 배포하는 것은 서로 다른 단계다.

## CI와 CD

CI는 변경 사항을 자주 통합하면서 빌드와 테스트 같은 검증을 자동으로 실행하는 개발 방식이다. 문제를 통합 과정에서 빠르게 발견하는 데 도움이 된다.

CD는 문맥에 따라 지속적 제공(Continuous Delivery) 또는 지속적 배포(Continuous Deployment)를 뜻한다. 전자는 배포 가능한 상태를 유지하며 운영 배포에 승인 단계를 둘 수 있고, 후자는 조건을 통과한 변경을 자동으로 운영 환경에 배포하는 방식이다.

## GitHub Actions의 구성

| 요소 | 역할 |
| --- | --- |
| 이벤트 | push나 pull request처럼 실행을 시작하는 계기 |
| 워크플로 | 자동화할 전체 흐름 |
| 작업(job) | 실행 단위 |
| 단계(step) | 작업 안에서 수행하는 개별 명령이나 액션 |
| 러너 | 작업이 실행되는 환경 |

복습용 흐름은 변경 제출, 코드 검사, 테스트, 빌드, 배포 판단으로 구성할 수 있다. 이 글은 개념 정리이며 실제 저장소에 자동 배포 설정을 추가한 것은 아니다.

## 검사가 통과했다는 의미

자동 검사는 미리 정의한 기준만 확인한다. 테스트가 통과해도 빠진 요구사항이나 모든 오류가 없다고 보장되지는 않는다. 무엇을 검사하고 실패하면 어디서 멈추는지를 함께 이해해야 한다.

## 복습한 내용

CI/CD는 반복되는 검증과 배포 절차를 일관되게 수행하고 변경의 문제를 빨리 발견하는 흐름으로 이해했다.
