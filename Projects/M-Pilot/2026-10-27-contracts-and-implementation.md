# 함수 계약과 구현 완료를 구분하기

정리일: 2026-10-27

## 확인한 자료

- `m-pilot/mpilot/db/parser.py: parse_manuals`
- `m-pilot/mpilot/db/vectordb.py: rebuild_search_index`
- `mpilot-handoff/mpilot-handoff/FUNCTION_SHEET_2026-10-27.md`

위 경로는 제공받은 로컬 폴더 기준이다. 현재 프로젝트와 기능별 인계본을 구분하며, 인계본의 병합 여부는 확인하지 않았다.

## 코드에서 확인한 내용

현재 프로젝트의 parse_manuals와 벡터DB 공개 함수들은 입력·반환값·예외를 설명하지만 본문은 생략 기호(...)로 남아 있다. 반면 인계 폴더에는 기능별 구현 파일이 별도로 존재한다.

## 배운 점

함수 이름과 설명이 갖춰졌다는 사실은 호출 계약을 논의할 수 있다는 뜻이다. 실제로 PDF를 처리하거나 색인을 만들 수 있다는 증거와는 구분해야 한다. Python 함수 본문에 ...만 있으면 그 자체로 미구현 오류를 던지는 것도 아니다.

## 검증 범위와 주의점

검토할 때는 ‘명세에 있는가 → 본문이 구현되어 있는가 → 호출 경로에 연결되어 있는가 → 검증했는가’를 각각 확인한다. 인계 코드가 현재 프로젝트에 통합되었다고 추정하지 않는다.

소스와 테스트 정의를 읽어 정리했다. 앱 실행, DB 연결, API 호출, 테스트 실행은 하지 않았으며 원본 프로젝트 파일을 수정하지 않았다. 팀 프로젝트 전체의 단독 구현을 주장하는 기록이 아니다.
