# CI 설정과 테스트 통과 증거를 구분하기

정리일: 2026-10-27

## 확인한 자료

- `m-pilot/.github/workflows/ci.yml`
- `m-pilot/tests/test_parser_types.py`
- `mpilot-handoff/mpilot-handoff/code/feature-vectordb-rebuild-index/tests/test_vectordb_indexing.py`

위 경로는 제공받은 로컬 폴더 기준이다. 현재 프로젝트와 기능별 인계본을 구분하며, 인계본의 병합 여부는 확인하지 않았다.

## 코드에서 확인한 내용

CI 설정은 main·develop 대상 push와 PR에서 Python 3.12와 MySQL 8.0 서비스를 준비하고 python -m pytest를 실행한다. 파서 테스트에는 잘못된 값 거부와 경계값 사례가 있다.

## 배운 점

자동 검사 명령이 저장소에 있다는 사실과 해당 커밋의 검사 결과가 성공이라는 사실은 다르다. 또한 인계 폴더의 테스트가 현재 프로젝트의 CI 대상에 포함되었다고 가정하면 안 된다.

## 검증 범위와 주의점

실제 실행 증거에는 대상 커밋, 실행 환경, 성공·실패 결과가 필요하다. 이번에는 원본 디렉터리 읽기 전용 요청을 지키기 위해 테스트를 실행하지 않았다. CI의 임시 DB 설정값도 학습 글에 복제하지 않았다.

소스와 테스트 정의를 읽어 정리했다. 앱 실행, DB 연결, API 호출, 테스트 실행은 하지 않았으며 원본 프로젝트 파일을 수정하지 않았다. 팀 프로젝트 전체의 단독 구현을 주장하는 기록이 아니다.

## 복습 질문

‘테스트가 있다’와 ‘이 버전을 테스트했다’를 각각 입증할 자료를 적기.
