# LLM 판단과 분리한 업무 규칙

정리일: 2026-10-27

## 확인한 자료

- `m-pilot/mpilot/models.py: is_self_guide_candidate, has_customer_procedure, raise_if_case_completed`

위 경로는 제공받은 로컬 폴더 기준이다. 현재 프로젝트와 기능별 인계본을 구분하며, 인계본의 병합 여부는 확인하지 않았다.

## 코드에서 확인한 내용

is_self_guide_candidate는 심각도가 HIGH이면 먼저 False를 반환하고, 그 외에는 조치 담당이 CUSTOMER인지 확인한다. has_customer_procedure는 허용 절차 ID 목록의 존재를 따로 확인한다.

## 배운 점

후보 여부와 실제 안내에 필요한 절차 존재를 나누면 어디서 조건을 충족하지 못했는지 설명하기 쉽다. 같은 입력에 같은 결과가 필요한 업무 분기를 모델의 자연어 판단에 맡기지 않는 구조다.

## 검증 범위와 주의점

후보=True만으로 전체 셀프 가이드가 성공했다는 뜻은 아니다. 근거 조회나 답변 검증은 이후 단계에 남는다. 완료된 건의 변경 차단도 별도 함수로 표현되어 있다.

소스와 테스트 정의를 읽어 정리했다. 앱 실행, DB 연결, API 호출, 테스트 실행은 하지 않았으며 원본 프로젝트 파일을 수정하지 않았다. 팀 프로젝트 전체의 단독 구현을 주장하는 기록이 아니다.
