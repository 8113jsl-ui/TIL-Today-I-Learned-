# 고객에게 보여 줄 모델을 따로 두기

정리일: 2026-10-27

## 확인한 자료

- `m-pilot/mpilot/models.py: CaseDetail, CustomerCaseResult`

위 경로는 제공받은 로컬 폴더 기준이다. 현재 프로젝트와 기능별 인계본을 구분하며, 인계본의 병합 여부는 확인하지 않았다.

## 코드에서 확인한 내용

CaseDetail은 신고·에러코드·조치 결과를 묶는다. CustomerCaseResult는 고객 화면용 필드만 정의하고 내부 원인과 guide_failure를 포함하지 않는다.

## 배운 점

내부 객체를 그대로 직렬화하기보다 공개용 모델을 두면 노출할 필드가 코드에 드러난다. 내부 데이터가 늘어나도 공개 응답에 자동으로 따라가지 않게 검토할 수 있다.

## 검증 범위와 주의점

모델 분리만으로 접근 제어가 완성되지는 않는다. 서비스가 실제로 공개용 모델로 변환하는지, 권한 없는 사용자가 내부 조회를 호출할 수 없는지는 별도 확인 대상이다.

소스와 테스트 정의를 읽어 정리했다. 앱 실행, DB 연결, API 호출, 테스트 실행은 하지 않았으며 원본 프로젝트 파일을 수정하지 않았다. 팀 프로젝트 전체의 단독 구현을 주장하는 기록이 아니다.

## 복습 질문

내부 필드가 추가되었을 때 고객 응답에 노출되지 않는지 확인할 테스트를 적기.
