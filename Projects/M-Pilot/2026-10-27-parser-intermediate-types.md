# PDF 파서의 중간 타입을 공유 계약으로 만들기

정리일: 2026-10-27

## 확인한 자료

- `m-pilot/mpilot/db/parser.py: RawTable, ChunkDraft`
- `m-pilot/tests/test_parser_types.py`

위 경로는 제공받은 로컬 폴더 기준이다. 현재 프로젝트와 기능별 인계본을 구분하며, 인계본의 병합 여부는 확인하지 않았다.

## 코드에서 확인한 내용

RawTable은 표의 쪽·순서·좌표·캡션·셀 목록을 담고, ChunkDraft는 번호를 매기기 전 text/table/ocr 초안을 담는다. 표 셀과 캡션에는 None을 허용한다.

## 배운 점

각 처리 단계가 같은 중간 타입을 주고받으면 본문 추출과 표 추출을 분담해도 다음 단계가 기대하는 필드를 명확히 할 수 있다. 최종 Chunk와 초안을 분리한 것은 번호 부여 전후의 책임을 구분하는 데 도움이 된다.

## 검증 범위와 주의점

초안의 section=None은 정보가 아직 없다는 의미다. 빈 문자열이나 임의의 절 번호로 덮어쓰면 누락 상태를 구분하기 어려워진다. 후속 단계의 절 상속 동작은 해당 구현을 별도로 확인해야 한다.

소스와 테스트 정의를 읽어 정리했다. 앱 실행, DB 연결, API 호출, 테스트 실행은 하지 않았으며 원본 프로젝트 파일을 수정하지 않았다. 팀 프로젝트 전체의 단독 구현을 주장하는 기록이 아니다.

## 복습 질문
