# 완료 처리에서 조건부 UPDATE와 행 수 확인

정리일: 2026-10-27

## 확인한 자료

- `mpilot-handoff/mpilot-handoff/code/feature-rdb-chat-resolution/mpilot/db/rdb.py: save_confirmed_resolution`

위 경로는 제공받은 로컬 폴더 기준이다. 현재 프로젝트와 기능별 인계본을 구분하며, 인계본의 병합 여부는 확인하지 않았다.

## 코드에서 확인한 내용

완료 처리 구현은 열린 지원 건을 잠근 뒤 완료 시각을 확인한다. 아직 접수 또는 조치 중인 지원 건만 UPDATE하고, 변경된 행 수가 1이 아니면 상태 오류를 낸다. 조치 기록 삽입도 같은 트랜잭션에 있다.

## 배운 점

완료 상태를 확인한 뒤 무조건 쓰는 방식보다 갱신 조건을 SQL에도 남겨 두면 변경 시점의 상태를 다시 확인할 수 있다. 조치 기록의 중복 충돌도 상태 오류로 변환한다.

## 검증 범위와 주의점

현재 구현은 완료 시각이 접수 시각보다 빠르면 저장하지 않는다. 예외가 어디서 발생하든 완료 상태와 조치 기록의 정합성을 확인하는 통합 테스트가 필요하다.

소스와 테스트 정의를 읽어 정리했다. 앱 실행, DB 연결, API 호출, 테스트 실행은 하지 않았으며 원본 프로젝트 파일을 수정하지 않았다. 팀 프로젝트 전체의 단독 구현을 주장하는 기록이 아니다.
