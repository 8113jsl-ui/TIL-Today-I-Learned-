# Docker 컨테이너와 실행 환경

학습일: 2026-08-28

수업에서는 Docker를 화물 컨테이너에 비유했다. 실행에 필요한 환경을 묶어 다룬다는 점은 도움이 되지만 컴퓨터 전체를 복사하는 것과는 구분해야 한다.

## 컨테이너가 필요한 상황

내 컴퓨터에서는 동작하는데 다른 환경에서는 라이브러리 버전 때문에 실패할 수 있다. 컨테이너는 애플리케이션과 필요한 파일을 격리된 환경에서 실행하도록 돕는다.

웹 화면, API, 데이터베이스를 각각 별도 구성 요소로 생각해 볼 수 있다. 각 구성 요소를 독립적으로 실행하고 연결하는 구조다.

## 가상머신과의 차이

가상머신은 자체 운영체제 커널을 포함하는 방식인 반면, 컨테이너는 실행 환경의 커널을 공유하는 격리된 프로세스다. 데스크톱에서는 컨테이너 실행을 위해 가상머신이 함께 사용될 수도 있다.

컨테이너를 쓴다고 운영체제나 CPU 구조 등 실행 조건이 모두 사라지는 것은 아니다.

## 복습용 점검 질문

- 어떤 버전의 실행 환경을 사용하는가?
- 외부에서 접속할 포트를 어떻게 연결하는가?
- 데이터는 어디에 보관하는가?
- 환경 설정은 어떻게 전달하는가?

환경을 묶어 실행하는 것뿐 아니라 서비스에 필요한 연결과 데이터 보관도 함께 설계해야 한다.

## 복습한 내용

Docker를 프로그램을 담는 상자로만 외우지 않고 실행 환경을 일정하게 구성하고 관리하는 도구로 이해했다.
