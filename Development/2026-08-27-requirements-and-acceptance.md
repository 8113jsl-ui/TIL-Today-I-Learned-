# 요구사항과 완료 기준을 먼저 정리하기

학습일: 2026-08-27

수업에서 PRD, 기술 문서, 체크리스트를 먼저 정리하는 방법을 배웠다. 할 일 앱을 예로 들어 복습했다.

## 만들 것과 만드는 방법

제품 요구사항에는 사용자가 해결하려는 문제와 필요한 기능을 적는다. 기술 문서에는 그 기능을 어떤 구조로 구현할지 적는다. PRD나 TRD라는 약어의 사용 범위는 팀마다 다를 수 있으므로 문서의 목적을 함께 명시하는 편이 좋다.

| 질문 | 복습용 예시 |
| --- | --- |
| 누가 사용하는가? | 개인 학습자 |
| 무엇을 하는가? | 공부할 일을 추가하고 완료 표시 |
| 어떻게 구현하는가? | 웹 화면, API, 데이터베이스 연결 |
| 무엇으로 확인하는가? | 저장 후 다시 조회해도 내용 유지 |

## 완료 기준은 확인할 수 있게

'저장이 잘 된다'보다 '제목을 입력하고 저장하면 목록에 나타나며, 다시 조회해도 남는다'가 확인하기 쉽다. 빈 제목은 어떻게 처리할지, 실패했을 때 무엇을 보여 줄지도 정한다.

체크리스트는 체크했다는 사실보다 확인 근거가 중요하다. 실행 결과나 화면 상태를 함께 기록하면 구현한 사람과 검수하는 사람이 같은 기준으로 판단할 수 있다.

## 복습한 내용

기능 요청, 구현 방법, 완료 기준을 연결하면 빠뜨린 부분을 찾기 쉽다. AI에게 구현을 맡기더라도 기준을 정하고 결과를 확인하는 일은 개발자가 해야 한다.
