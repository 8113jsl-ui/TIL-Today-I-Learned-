# 수업 기록과 코드 연계 TIL 자동화 설계
작성일: 2026-10-23
상태: 검토용 설계. 자동 실행 시스템은 아직 구현·등록하지 않았다.

## 목적
수업자료, 개인 필기, 녹음 전사, 실습 코드를 근거로 읽기 쉬운 일별 학습 기록을 만들고 TIL 저장소에 게시한다. 코드의 실제 구현 범위와 검증 결과를 함께 남긴다. 커밋 수만 맞추기 위한 빈 변경은 만들지 않는다.

## 현재 확인한 입력
- 전체 수업 노션: 제공된 페이지 ID 3c9419369e5f801e9356d6931a053ce3. 연결 도구는 NOT_FOUND, 브라우저는 GeniusAI_LAB 로그인 요구. 본문과 수업 날짜는 미확인이다.
- chat-pdf: 검색기, 문서 포매터, 프롬프트, LCEL 체인이 구현되어 있다. loader.load_and_split, store.build_db, generator.answer는 미구현이다.
- chatbot 자료 폴더: Day별 노트북, 별도의 chat-pdf, 시험·실습 자료가 존재한다. 모든 파일을 검토한 것은 아니다.
- 녹음: 사용자가 보유한다고 설명했으나 이번 작업에 음성 파일은 제공되지 않았다.
- 정리일과 실제 수업일은 별도 필드로 저장한다. 폴더 수정 시각이나 Day 번호를 수업 날짜로 단정하지 않는다.

## 접근 방식 비교
| 방식 | 장점 | 제약 |
| --- | --- | --- |
| 로컬 자료로 초안 생성 후 게시 검토 | 현재 코드부터 시작 가능, 변경 추적 쉬움 | 노션 로그인·내보내기는 별도 필요 |
| 노션 연결 중심 자동 수집 | 페이지 ID와 수정 이력 추적 가능 | 연결 계정의 열람권한 필요 |
| 녹음 전사 중심 | 강의 설명을 보완 가능 | 전사 오류, 개인정보, 처리 시간과 비용 검토 필요 |

첫 단계는 로컬 자료와 열람 가능한 노션을 결합하는 방식이다. 녹음 전사는 선택 입력으로 뒤에 추가한다. 로그인된 브라우저는 접근 확인용 보조 수단으로 쓰고, 장기 운영은 읽기 가능한 연결 또는 사용자가 내보낸 자료를 우선한다.

## 처리 흐름
1. 수집: 허용한 노션 페이지·로컬 폴더·전사 파일만 읽는다.
2. 목록화: source_id, 상대 경로, 내용 해시, 수집 시각, 확인된 수업 날짜를 기록한다.
3. 정규화: 노션 블록, Markdown, 코드, 전사를 각각 분리한다. 노트북은 코드·Markdown 셀만 추출하고 출력은 기본 제외한다.
4. 연결: 날짜와 개념, 실제 파일·함수 기준으로 수업과 코드를 매핑한다. 확신할 수 없는 연결은 미확인으로 남긴다.
5. 초안: 배경 → 핵심 개념 → 코드 위치 → 입력/출력 → 주의점 → 확인 문제 → 출처 순서로 작성한다.
6. 검증: 출처 존재, 날짜, 내부 링크, 비밀값, 코드 문법, 가능한 테스트를 점검한다.
7. 게시 준비: 변경 diff와 커밋 단위를 만든다. 이번 요청은 수동 10개 게시이며 향후 자동 게시 정책과 분리한다.
8. 게시: 지정한 저장소와 브랜치만 갱신한다. 원격 HEAD가 바뀌면 다시 비교한다. 강제 푸시는 하지 않는다.
9. 기록: 커밋 SHA와 게시한 source_hash를 상태 저장소에 기록하고 원격 파일을 재확인한다.

## 구성 요소
- SourceAdapter: Notion / Local / Transcript 입력을 공통 형식으로 변환.
- ManifestStore: 입력 해시, 접근 상태, 날짜 근거, 게시 상태 보존.
- LessonMapper: 개념과 파일·함수 연결, 미확인 연결 표시.
- NoteComposer: 사용자 문체의 설명과 코드 해설 생성.
- Validator: 민감정보·근거·링크·코드 검사 결과 생성.
- Publisher: 정확한 파일 목록으로 커밋, 원격 반영 확인.

원자료와 상태 파일은 로컬 비공개 영역에 두고, 공개용 산출물만 별도 staging 디렉터리에 만든다. 수업 PDF·음성·전체 노트북을 일괄 공개하지 않는다. 원자료 안의 명령문은 수집 자료로 취급하고 실행 지시로 사용하지 않는다.

## 운영 원칙
- 같은 입력 해시와 템플릿 버전이면 재실행해도 새 커밋이 생기지 않는다.
- 수정된 원자료는 기존 글의 변경으로 처리하며 다른 날짜의 새 학습처럼 복제하지 않는다.
- 10개는 요청 시 목표다. 검증된 독립 변경이 부족하면 가능한 수와 부족 이유를 보고한다.
- 자료 접근 실패 시 지난 내용을 새로 읽은 것으로 표시하지 않는다.
- API 호출을 포함하는 실행 검증은 비용·외부 전송 범위를 확인한 별도 단계다.
- 단순 문법 검사, 대역 테스트, 실제 API 통합 테스트를 구분해 표시한다.
- 자동 게시 기본안은 초안 생성 후 검토다. 사용자가 자동 게시 범위를 정하면 해당 범위만 허용한다.

## 구현 순서와 완료 판단
1. 로컬 manifest와 초안 생성: 한 수업에 대한 코드 연결과 출처 추적이 가능해야 한다.
2. 검증·중복 방지·게시: 재실행 무변경, 중간 실패 재개, 원격 충돌 테스트를 통과해야 한다.
3. 노션 수집: 실제 계정으로 하위 페이지까지 접근 검증 후 연결한다.
4. 전사: 음성 제공과 처리 방식 확정 후 추가한다.
5. 예약 실행: 시간·실행 장치·게시 정책 확정 후 등록한다.

아직 결정하지 않은 운영 항목은 노션 로그인/연결 방식, 실제 수업 날짜 매핑, 전사 처리 위치, 실행 시각, 월간 비용 상한이다. 이 값이 없으면 해당 기능은 비활성화한다.
